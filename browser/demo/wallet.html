aztec-avm-runtime — transfer_in_public, through a wallet

This is a simulator. No proofs are produced, there is no L1 and no network. Every receipt carries simulated: true and proving: 'none'. The runtime tells the wallet so, in upstream's own AppCapabilities.metadata field, before it asks it for anything — and the wallet records that it was told.

The wallet on the other end of the channel is a debugging wallet, and it is deliberately the opposite of a production one: its keys are derived from a recorded seed so a recording replays identically, and every decision it makes is written into the .ct container as a trace record. Those are properties a real wallet cannot have and this one should. See DEV-WALLET.md.

The channel is a MessageChannel carrying Aztec's own wallet protocol — discovery, ECDH P-256 key exchange, an AES-256-GCM session — which is M33's boundary, unchanged. Nothing here reaches around it: the contract registration, the transaction and its submission all cross as encrypted SECURE_MESSAGEs.
